# Marrow UI — Original Source 1:1 Reconstruction Rules

## 1. Core objective

Reconstruct the original Marrow UI faithfully at a 1:1 level by arranging, integrating, and restoring the genuine original source files and their verified dependencies. The objective is not to design a replacement, demo, approximation, or independently implemented replica.

## 2. Original source code only

- Work exclusively with genuine original Marrow application source files and verified dependencies: original APK/decompiler evidence, layouts, resources, drawables, styles, themes, dimensions, strings, bindings, navigation, and behavior.
- Arrange and integrate existing original files in their correct locations and relationships.
- Preserve the original UI hierarchy, component properties, dimensions, spacing, typography, colors, navigation, and behavior wherever supported by verified source evidence.
- Do not replace original components with independently designed replicas.
- Do not invent missing implementation details or assume how the original UI should look or behave.
- If a source element or dependency cannot be verified, record it as unresolved rather than fabricating a replacement.

## 3. No fabrication or contamination

- Zero fabrication, zero contamination, and zero unauthorized implementation.
- Do not introduce invented code, layouts, components, assets, data, or behavior.
- Do not mix files, resources, UI elements, implementation details, or dependencies from unrelated applications or projects.
- Do not overwrite genuine source files with speculative implementations.
- Work only in this repository: `Deepaksah123/Bone-marrow-`. Do not move this work to another repository or project.

## 4. No screenshot-based implementation

- Do not use screenshots as implementation material, source assets, UI backgrounds, or substitutes for original layouts and components.
- Do not draw over screenshots or copy screenshot pixels into the application.
- Screenshots may be used for QA and comparison only; they must not be used to invent or implement UI elements.
- Build exclusively from genuine original source files and verified dependencies.

## 5. One major, continuous work batch

- Work in large, cohesive batches rather than fragmented micro-steps.
- Select a substantial, clearly defined reconstruction batch and continue through source inspection, file integration, compilation, and applicable validation.
- Integrate related original files and dependencies together.
- Do not stop after documentation, validation scripts, or minor cosmetic adjustments while the actual reconstruction remains unfinished.
- Do not report a batch as complete while implementation or validation is unfinished.

## 6. Keep work focused and report only verified results

- Remain focused exclusively on the reconstruction work.
- Avoid unnecessary explanations, repetitive status updates, and unrelated suggestions.
- Report meaningful implementation results, verified blockers, and actual completion status.
- Never claim that files were changed, work was performed, tests passed, or reconstruction is complete without corresponding evidence.

## 7. User content remains deferred

- The user will provide their own content later.
- Until then, reconstruct original UI structure and behavior from genuine source files only.
- Do not invent or insert subjects, questions, tests, video metadata, user records, progress values, or other content.
- Preserve original content-binding mechanisms and leave user-content-dependent fields unpopulated where appropriate.
- Do not fabricate content merely to make a screen appear complete.

## 8. Exclusions

Do not add ads, subscriptions, plan upgrades, renewals, payment, checkout, or upsell UI. Do not import material from unrelated apps or repositories.

## 9. Definition of done

A reconstruction batch is complete only when all applicable conditions below are met:

1. Relevant original source files and dependencies have been identified and correctly arranged.
2. The corresponding UI has been reconstructed from genuine original implementation files, not speculative replacements.
3. Original hierarchy, styling, dimensions, and interactions are preserved to the extent supported by verified source evidence.
4. No unrelated application material, fabricated content, or unauthorized implementation has been introduced.
5. The application builds successfully and applicable functional checks pass.
6. Unresolved source gaps and unverified parity claims are explicitly identified.

## Non-negotiable rule

Do not invent. Do not fabricate. Do not contaminate. Do not independently redesign. Do not use screenshots as implementation. Do not substitute self-written approximations for genuine original source files.

The task is to arrange, integrate, and faithfully reconstruct the original Marrow UI from its genuine source code into a 1:1 implementation. All work must remain within that scope until the selected major reconstruction batch is finished and validated.
